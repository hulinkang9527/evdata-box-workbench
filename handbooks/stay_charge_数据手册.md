## 一、数据集概述与背景

### 1.1 业务场景

本数据集为面向商学院本科教学与研究场景设计的新能源车行为数据集，来源于车辆运行上报数据与地理空间数据的融合加工，涵盖车辆在城市空间中的停留与充电全链路行为。数据集核心聚焦"人-车-场-站"四维关联，旨在支撑以下核心教学目标：

* **社区充电需求分析**：还原车辆在社区、商业体及充电站之间的停留与补能路径，识别不同场景下的充电需求特征；

* **用户行为画像构建**：结合车辆静态属性与充电行为指标，构建充电用户分群，训练商业分析中的画像建模能力。

* **场站运营诊断**：基于充电站的时段分布、功率特征与利用率，诊断场站运营效率，支撑分时定价与排班决策练习；

### 1.2 数据来源

数据由多源数据融合加工而成，主要来源包括：

| 来源系统                  | 对应表                              | 抽取方式                 |
| --------------------- | -------------------------------- | -------------------- |
| 车辆采集数据（GB/T 32960 协议） | trip\_stay\_charge\_data（停留事件主表） | 按停留事件触发采集，经脱敏后批量落地   |
| 车型公告与厂商公开参数           | vehicle\_model\_info（车型信息表）      | 工信部公告目录及厂商公开参数整理     |
| 网络公开充电设施信息            | charge\_station\_info（充电站属性表）    | 网络公开信息采集，与车辆充电数据交叉校验 |
| 地图服务商 AOI 数据          | aoi\_info（AOI属性表）                | 地图服务商兴趣面（AOI）边界数据    |

### 1.3 适用场景与慎用建议

**适用场景：**

* 快充场站运营节律分析（峰谷特征、工作日/休息日/法定节假日需求差异、设施利用率评估）

* 充电用户行为画像与分群（应急补电型 / 日常顺便充型 / 夜间驻扎型等行为模式识别）

* 社区充电配套缺口识别（网格匹配与空间覆盖充分性评估）

* 商学院本科教学中的数据分析、可视化与商业决策建模实践（Excel / Tableau 可完成）

**慎用场景：**

* **不适合区域外推**：数据仅覆盖选定的社区、商业体及4个快充站，区域外停留充电行为不可见，不宜外推至全市层面的结论。


* **不适合短时行为分析**：停留时长不足10分钟且未充电的记录已被过滤，短时过路或排队后离开的行为未纳入，分析周转率时需注意口径。

* **不适合真实日期还原**：时间戳虽已保留标准日期时间格式，但具体日期经偏移脱敏，不可与外部按真实日历日期组织的数据直接对接。

### 2.3 关联逻辑说明

* **trip\_stay\_charge\_data.evdata\_model\_id → vehicle\_model\_info.evdata\_model\_id**：多对一关系。每条停留记录通过车型代码关联到唯一车型。

* **trip\_stay\_charge\_data.cdz\_id → charge\_station\_info.cdz\_id**：多对一关系。仅在车辆停留于充电站内时取值；停在非充电站区域时该字段为空。

* **trip\_stay\_charge\_data.uid → aoi\_info.uid**：多对一关系。仅在车辆停留于社区/商业体 AOI 时取值；停在非 AOI 归属地时该字段为空。

* **空间关联**：charge\_station\_info 与 aoi\_info 之间无外键，需通过各自的 1km 网格编码字段（`场站所在网格（1km）` / `aoi所在网格(1km)`，格式如 121.2-31.42进行空间邻近匹配。

## 三、数据质量与治理

### 3.1 数据血缘与加工流程

```
[车辆运行上报 GB/T 32960] ──→ [停留事件识别] ──→ [脱敏处理] ──→ [停留事件主表]
                                 （AOI围栏停留>10分钟     （ID脱敏编码、
                                   或期间发生充电）        日期偏移）
[工信部公告/厂商参数] ────────────→ [整理归类] ────────────→ [车型信息表]
[网络公开充电设施信息] ──→ [与充电数据交叉校验] ──────────→ [充电站属性表]
[地图服务商 AOI 数据] ────→ [边界与网格映射] ─────────────→ [AOI属性表]
```

**加工环节说明：**

1. **采集层**：行为数据由车辆按 GB/T 32960 协议上报，依据 GPS 轨迹与 BMS 状态识别 AOI 围栏内的停留事件。
2. **清洗与脱敏层**：停留超过10分钟或期间发生充电的记录予以保留，其余过滤；车辆/车型ID已脱敏编码，日期整体偏移，但保留真实时分秒、星期分布（week\_n）与日期类型（day\_type）。
3. **校验层**：运营商、桩数等场站属性与车辆充电行为交叉校验后入库；AOI 与场站统一映射至 1km×1km 网格编码。
4. **输出层**：按四张关联表组织，输出为 Excel 工作簿。

### 3.2 数据质量校验结论

**经校验，本数据集无已知数据质量问题。** 枚举值、取值范围、外键引用完整性、时间逻辑（起止先后、时长一致性、充电时段包含于停留时段）等校验均通过（详见 3.3）。

需要说明的是，数据中存在若干由**采集规则、脱敏规则与业务口径**决定的特征（如停留不足10分钟的记录过滤、日期偏移脱敏、充电字段按规则置空、桩数为推断参考值、停留 SOC 与充电 SOC 采样时点不同等），这些均不属于数据缺陷，而是使用前必须了解的口径前提。检验中发现的使用层面问题（如主表记录级唯一键的选取、充电量与功率的交叉验证口径）已统一收入 **第六章 使用建议与避坑指南**，请在使用前务必阅读。

### 3.3 数据一致性校验

* **主键唯一性**：cdz\_id、evdata\_model\_id、uid 分别为充电站属性表、车型信息表、AOI属性表的主键，在各自表内唯一。停留事件主表的 evdata\_vehicle\_id 因一车多条记录而不唯一，使用建议见第六章第 9 条。

* **外键引用规则**：主表中的 evdata\_model\_id、cdz\_id、uid 均按外键规则关联到对应主表；cdz\_id 与 uid 允许按业务规则为空（业务含义见第六章第 2 条）。

* **时间一致性**：日期经偏移后与真实日历不对应，且偏移非整周平移——**偏移后的时间与 week\_n、day\_type 不保持对应关系**；week\_n（星期数）与 day\_type（工作日/休息日/法定节假日）各自保留真实分布，可独立使用。

## 六、使用建议与避坑指南

### 6.1 最容易犯的错误

#### 1. 把"未充电"记录的空值当作 0 参与计算

未充电记录（charge\_or\_not = 0）中，c\_s\_time、c\_e\_time、charge\_start\_soc、charge\_end\_soc、charge\_duration、c\_max\_power 均为**空值**。做充电时长、充电量、功率等统计时，务必先以 `charge_or_not = 1` 过滤，切勿将空值填充为 0 后纳入均值计算——这会严重拉低真实充电行为的统计结果。

#### 2. 误删 cdz\_id 或 uid 为空的记录

cdz\_id 为空表示车辆停在**非充电站区域**，uid 为空表示车辆停在**非 AOI 归属地**——空值本身携带"社区无桩、外出充电"等关键业务信息，直接删行会系统性丢失社区充电缺口分析所需的样本。

#### 3. 把时间戳当真实日历日期使用

s\_time、e\_time 等字段已保留标准日期时间格式（如 `2024-04-11 19:54:10`），但**具体日期经脱敏，并非真实日历日期**。不可与外部按真实日期组织的数据（天气、节假日历、油价等）直接关联。尤其注意：**脱敏后的日期与 week\_n、day\_type 不保持对应关系**，无法从日期反推星期或日期类型。做时间维度分析时，应优先使用真实的 week\_n（星期分布）与 day\_type（工作日/休息日/法定节假日）。

#### 4. 忽略停留不足10分钟的过滤规则

数据集只保留停留超过10分钟或期间发生充电的记录。分析场站周转率、排队时长时，需意识到短时过路与排队后离场的行为不在样本内，结论不可外推到全部到访车辆。

#### 5. 把推断的桩数与运营商当作实测容量

快充枪数、慢充枪数、运营商来源于网络公开信息推断，非实时接入数据，可能与实际存在偏差。测算场站利用率时建议将其作为上限参考，并结合主表观测到的最大功率（c\_max\_power）与同时充电车辆数交叉验证。

### 6.2 重要注意事项

#### 6. brand\_level 为人工划分，存在主观性

品牌级别（豪华/非豪华/自主豪华）是基于市场价格与品牌定位的人工划分，非官方标准。做品牌维度对比时建议说明划分口径，必要时改用 vehicle\_type、car\_level 等公告口径字段。

#### 7. 1km 网格空间匹配存在精度损失

充电站与 AOI 的空间关联通过 1km×1km 网格编码完成，网格边缘附近的场站可能被归入相邻网格。做"社区周边充电覆盖"类分析时，建议对网格匹配结果做缓冲半径的敏感性检查。

#### 8. 跨天停留记录需按起止时间成对使用

部分记录跨越午夜（开始于 23:55、结束于次日 01:59）。按"天"统计停留或充电量时，直接使用 s\_time 所在天会把跨天记录整天计入开始日，建议按时长拆分或统一口径后再聚合。

#### 9. 不要把 evdata\_vehicle\_id 当作记录级唯一键

同一辆车在数据集中可能有多条停留记录（不同时间、不同地点），evdata\_vehicle\_id 标识的是车辆而非停留事件。**直接按 evdata\_vehicle\_id 去重会丢失同一车辆的后续停留记录**，导致车辆行为分析严重失真。需要记录级唯一键时，建议使用（evdata\_vehicle\_id, s\_time）组合或自行生成自增序号；做车辆级统计时，应先明确"按车聚合"还是"按停留事件聚合"。

#### 10. 充电量与"最大功率×时长"可能不一致

c\_max\_power 是充电过程中的实际峰值功率，而平均功率通常低于峰值。部分记录中，按"SOC 增量 × 电池额定能量"估算的充电量会超过"峰值功率 × 充电时长"的理论上界，说明 SOC 读数或时长记录存在一定误差。涉及充电功率、充电速度、充电量的精细分析时，建议交叉验证并谨慎解读，不宜将单条记录的推算值作为精确结论。

#### 11. 数据集不适用于经营测算与因果推断

数据集不含电价、费用等经营数据，且为观测数据、未经实验设计。不支持收入测算；涉及"场站建设是否提升充电便利性"等因果问题时，需额外设计准实验方法，不能直接从相关性推出因果性。
